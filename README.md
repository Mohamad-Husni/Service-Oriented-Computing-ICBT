## Run

Install the .NET 10 SDK from Microsoft. From this folder run:

```sh
bash scripts/build.sh
bash scripts/run.sh
```

Open http://127.0.0.1:5100. Roles: `customer`, `customer2`, `partner`, `operator`. Local demonstration password: `WaterDemo2026!`. Accounts: `100000001` and `100000002`. The operator is the prototype's restricted administrative role for meter updates. Tokens and password can be overridden with environment variables. They are deliberately public demonstration values, never production credentials.

Services: portal 5100, usage 5101, payments 5102. `PORT_BASE` changes all three ports. `DATA_ROOT` changes the persistent data directory. Run on a private loopback interface only. Stop with Ctrl+C. Data survives restarts. Do not delete a database while a service uses it.

## Desktop client

The .NET/Avalonia client runs on desktop platforms and uses the same Payment API as the browser. It does not access either database.

```sh
export PARTNER_TOKEN=demo-partner-token-change-me-001
dotnet run --no-build --project src/Water.Desktop
```

Click **Check balance**, enter an amount and a unique reference, then **Record payment**. Keep the reference unchanged to retry a request; enter a new reference for a different payment. `PAYMENTS_URL` overrides the default loopback service URL. For API-level verification without opening a desktop window, append `-- --smoke`.

## Source layout

- `Water.Contracts`: public payment message records; reusable by the API and .NET client.
- `Water.Shared`: validation, authentication/authorization helpers and SQLite connection utilities.
- `Water.Usage`: account details and cumulative readings; owns usage.db.
- `Water.Payments`: fixed bills, immutable receipts and balances; owns payments.db.
- `Water.Portal`: ASP.NET Core cookie-authenticated gateway and plain JavaScript web client.
- `Water.Desktop`: partner payment interface and typed HTTP consumer.
- `tests`: executable unit checks, real HTTP integration tests and Playwright browser checks.

## Verification

Run `dotnet run --no-build --project tests/Water.UnitTests`. For integration tests start services on a **new empty DATA_ROOT**, then run `python3 tests/integration.py`. Tests intentionally alter seeded accounts and must not target an existing demonstration database. The tests use Python's standard library. Set the same `PORT_BASE` for server and tests when using another port range.

For browser tests run `npm install`, `npx playwright install chromium`, then `npm run test:browser`. Browser checks require the default demo password. `tests/browser.cjs` writes screenshots and results into `evidence`. Source includes the latest captured logs; rerunning overwrites them. Unit checks are a small executable assertion harness rather than xUnit; no code-coverage percentage is claimed.

Build with `-p:UsedAvaloniaProducts=` to disable the optional Avalonia build statistics task in restricted environments. `scripts/build.sh` already sets this parameter. The desktop HTTP smoke checks test its actual PaymentClient; they do not establish native UI accessibility or Windows device compatibility.

## Scope

This is a demonstrable academic system. It does not include real bank settlement, customer self-registration, email delivery, official tariffs, meter replacement/reset, reconciliation or production identity management. Fixed identities and account seeds keep the assessment demonstration reproducible. Production adoption needs identity federation, per-partner provisioning, operational monitoring, reconciliation and a server database before horizontal service replication. The delivered report distinguishes implemented behaviour from these recommendations.
